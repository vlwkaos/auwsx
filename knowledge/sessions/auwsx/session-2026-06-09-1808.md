## create-override-coalesce-default

Pattern for exposing a subset of policy columns on a `create` without
duplicating SQL DEFAULTs in Rust. **The migration stays the single source of
default values.**

- `NewProject` gains `Option` override fields (`completion_policy:
  Option<CompletionPolicy>`, `plan_gate_timeout_min: Option<i64>`,
  `completion_soft_timeout_min: Option<i64>`). `None` ⇒ keep DB DEFAULT; `Some`
  ⇒ override only that column.
- `projects::create` does the base INSERT (unchanged columns take their DEFAULT
  via RETURNING id), then **conditionally** runs one UPDATE only when at least
  one override is `Some`:
  ```sql
  UPDATE projects SET
    completion_policy = COALESCE(?, completion_policy),
    plan_gate_timeout_min = COALESCE(?, plan_gate_timeout_min),
    completion_soft_timeout_min = COALESCE(?, completion_soft_timeout_min)
  WHERE id = ?
  ```
  Bind `completion_policy.map(|p| p.as_str())` (Option<&str>), `Option<i64>` direct.
  `COALESCE(NULL, col)` = keep the just-defaulted value ⇒ siblings untouched.
- Guard `if a.is_some() || b.is_some() || c.is_some()` skips the no-op write when
  all None (defaults persist on the INSERT alone).
- Why not bind defaults from Rust: would duplicate the migration's DEFAULT in two
  places. Why not dynamic SQL: COALESCE is one static statement, simplest form.
- This is the CRUD-layer cousin of the schema-level `review_agent_cmd NULL →
  work_agent_cmd` fallback already in db-schema.md.

## cli-parse-grammar (Parsed helper + optional-int contract)

The hand-rolled `parse`/`Parsed` CLI (auwsx-tui/src/cli.rs, no clap) gained:

- New flags on `project add`: `--completion-policy <manual|soft|auto>`,
  `--plan-gate-timeout <int>`, `--completion-timeout <int>` (maps to
  `completion_soft_timeout_min`). All optional → `None` when absent.
- New `Parsed::opt_int(key) -> Result<Option<i64>>`: absent ⇒ `Ok(None)`;
  present-but-not-an-integer ⇒ `Err` (rejected, NOT silently dropped). Fills the
  gap that `int()` (positional, required) left for optional flags.
- Enum flag idiom reused verbatim from `--source`/`--approval`/`--status`:
  `match p.flag("k") { Some(s) => Some(Enum::from_str(&s).with_context(...)?), None => None }`.
- `print_response` Project arm now prints a `policy:` line (completion / plan_gate
  / completion_soft / concurrency) so `project get`/`ls` verify the override took.

**Parser behavior gotchas pinned by tests (Parsed::new semantics):**
- A `--key` with NO following value (or followed by another `--`) becomes a
  boolean, so `opt_int` reads it as **absent → None, not an error**. Bare
  `--plan-gate-timeout` at end of args ⇒ `None`.
- `-5` does not start with `--`, so it is taken as the flag VALUE and `i64`
  accepts it ⇒ `Some(-5)`. No sign validation at parse OR DB layer (no CHECK on
  the timeout columns). Negative gate timeout behaves like 0 (always due).
- Repeated `--completion-policy auto --completion-policy soft` ⇒ HashMap insert
  overwrites ⇒ **last-wins** (`Some(Soft)`).
- `--key=value` equals-form supported (split_once('=')) for both enum and int flags.
- `from_str` is exact lowercase: `AUTO` and `" "` (whitespace) ⇒ `Err`; `--completion-policy=` (empty) ⇒ `Err`.
- i64 overflow (`9223372036854775808`) ⇒ parse `Err`.
