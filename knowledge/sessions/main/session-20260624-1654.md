## prompt-policy

Decision: auwsx should not put pipeline/process expectations into global
`AGENTS.md`. That spends context everywhere and creates duplicate authority.

Preferred model:
- Immutable auwsx worker contract stays built into prompt rendering.
- Persisted operator guidance becomes structured prompt policy/profile data.
- Prompt profiles are selected globally or per project.
- Profiles compose compact packaged snippets such as backpressure, good-to-go,
  no-repeat, human-verify, conflict handling, and merge verification.
- Project runtime knobs remain project-local: schedule, concurrency, merge,
  timeouts, skill path.
- User-editable guidance is bounded, labelled as non-secret operator guidance,
  delimited in prompts, and cannot override system/developer/repo controls.

Prompt render order:
1. auwsx immutable worker contract
2. selected auwsx prompt profile snippets
3. repo instructions
4. issue state, subtasks, findings, queue, reports
5. exact issue-scoped control protocol

## good-to-go-no-repeat-policy

Machine-verifiable checks should be promoted in this order:
- Executable tests: concrete bug/regression at a boundary.
- good-to-go axes: recurring review invariant not fully enforceable by one test
  yet, or a checklist that catches cross-surface drift.
- no-repeat breadcrumb: smallest local hint after a specific mistake or wrong
  assumption; prefer inline `^` comment at the offending code over AGENTS.md.
- memo/session knowledge: multi-faceted design decision or branch continuation.

So no-repeat is not the main machine-verification mechanism. It is the local
anti-repeat breadcrumb when a failure came from a specific code path or habit.

## backpressure-round-1

Completed before memo:
- Added `global_settings` singleton table/helper and IPC response.
- Injected Pipeline UX Standard into worker prompt headers.
- Rebuilt Settings as global-only and project config as project-row edit.
- Added capability-driven footer/action model and sectioned typed forms.
- Tests initially passed: `cargo test --package auwsx-core --package auwsx-tui`,
  no-run build, and dev build.
- Added good-to-go axis for singleton settings and IPC response coverage.

Backpressure round 1 failures to fix:
- Security: issue-local socket proxy currently forwards arbitrary IPC to daemon.
  Fix by filtering proxy commands with same issue allowlist as control outbox, or
  remove `AUWSX_SOCK` from issue workers. Add regression that
  `UpdateGlobalSettings` cannot pass issue-local control.
- Security: `pipeline_ux_guidance` is unbounded. Add max length, rows-affected
  check, and tests. Label field as not for secrets.
- Prompt safety: delimited operator-guidance block should state it cannot
  bypass controls, reveal secrets, or override system/developer/repo rules.
- CLI safety: escape or strip ASCII control characters when printing persisted
  guidance.
- Dependency policy: `chrono` direct use in auwsx-tui depends on workspace
  `0.4`; audit says pin to `=0.4.38` or explicitly update policy.
- TUI capability mismatch: Config should not advertise Enter edit/open for
  read-only rows, and hidden `p` project action should be gated.
- Test gaps: add global settings IPC roundtrip/dispatch tests, Pipeline UX row
  edit test, select/completion behavior tests, and stronger UI buffer assertions.

Simplify findings worth considering after blockers:
- Count form section transitions directly instead of allocating a `HashSet`.
- Add `prompt::preview_count()` instead of building preview prompts just to
  count phases.
- Consolidate repeated active-completion computations.
- Larger follow-up: deduplicate daemon-runtime command classification and
  pipeline failed-run finish handling.

## Trials & Solutions

- Tried treating Pipeline UX Standard as a simple editable prompt blob -> audit
  found persistent prompt-injection and DoS risk -> solution is bounded
  structured prompt policy/profile with immutable worker contract.
- Tried relying on outbox allowlist while still providing issue-local socket ->
  audit found arbitrary IPC bypass -> proxy must share the issue-scoped allowlist
  or socket must be removed from worker env.
- Good-to-go initially passed broad tests -> independent backpressure agents
  found missing targeted IPC/TUI/security tests -> add public-contract tests for
  singleton settings, capabilities, select/completion controls, and proxy deny.
