## remote-pr-merge-observation

- Added `RemoteProviderExecutor::observe_pull_request` as a provider-boundary operation distinct from PR create/update.
- GitHub adapter observes existing PRs with `gh pr view <number> --repo owner/repo --json number,url,id,state,headRefName,baseRefName,headRefOid,baseRefOid`.
- Added `remote_executor::observe_project_pull_requests`: for PR-merge projects, it scans `READY_TO_MERGE` issues with linked non-merged PRs, observes remote state, updates `remote_pr_links`, and records an inbound `remote_sync_runs(kind='pr')` audit row.
- If GitHub reports the PR as merged, auwsx writes a result report `Remote PR merged: <url>` and marks the local issue `DONE`.
- Scheduler ticks now run PR observation after queued remote sync execution and emit `IssueStatus(DONE)` for observed merges.
- Tests cover executor-level open→merged, open→open, and scheduler-level merged PR feedback into local `DONE`.

## Trials & Solutions

- Reusing the PR create/update action for observation would conflate two different provider operations -> added a separate trait method and observation function.
- PR observation needs operator/debug visibility -> each observation writes an inbound `remote_sync_runs(kind='pr')` row even when it only updates link state.
- Required-check policy is still only carried into PR creation planning -> left explicit check-state enforcement as a remaining item rather than claiming it in this slice.
