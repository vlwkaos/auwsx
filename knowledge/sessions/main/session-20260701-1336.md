## remote-pr-check-status

- Added migration `0021_remote_pr_status.sql` with `remote_pr_links.check_status`, `check_summary`, `merge_state_status`, and `review_decision`.
- Added `RemotePrCheckStatus` domain enum: `unknown`, `pending`, `success`, `failure`.
- `GithubCliRemoteExecutor` now asks `gh pr view` for `statusCheckRollup`, `mergeStateStatus`, and `reviewDecision`.
- PR observation persists normalized check status and summary counts onto `remote_pr_links`.
- Added IPC `GetIssueRemoteLinks` and `IssueRemoteLinks` so TUI can fetch issue/PR links without opening DB.
- Added serde defaults for new `RemotePrLink` fields so newer clients can decode older daemon payloads.
- TUI issue summary now renders `remote pr` with PR number, state, check status, summary, merge status, review decision, and URL.
- `require_green` remains observation-backed in this slice; GitHub branch protection is still the actual merge gate.

## Trials & Solutions
