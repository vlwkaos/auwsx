## architecture-overview

- Two-repo split: `wsx` (existing TUI, sibling at `/Users/vlwkaos/ws/wsx`) holds the worktree+tmux+git primitives in a new `wsx-core` library crate. `auwsx` consumes `wsx-core` via path dep (`../wsx/crates/wsx-core` relative to auwsx Cargo.toml — declared in both root workspace.dependencies and `crates/auwsx-core/Cargo.toml`).
- Daemon-first: a long-lived `auwsx daemon` (loaded via launchd at v0.1) owns SQLite, scheduler, pipeline, agent runners, the file-watch inbox, and the notification emitter. Front-ends (TUI v0.1, web v0.2) are thin observers + command issuers that talk over a Unix socket at `$XDG_RUNTIME_DIR/auwsx.sock`. Protocol is `Command` / `Event` JSON-lines (defined in `auwsx_core::ipc`).
- Pipeline is a state machine, NOT one mega-prompt. Each agent invocation receives a tight, focused prompt for one step (iterate / qa / commit / gh-pr / memo / dream). The orchestrator handles all glue (writes `.auwsx/plan.md` / `progress.md` / `summary.md` / `feedback-{n}.md`; reads `.auwsx/signal-done`).
- Five entity types in addition to projects+tasks: drafts (lightweight intent), followups (ad-hoc additions during iteration), routines (cron-driven main-branch prompts incl. built-in triage+deepsleep+dream+morning-summary), main_jobs (run records for any main-branch agent invocation), iterations (per-task run records).
- Followups auto-advance rule (Plan Step 3.8): on iteration end, if explicit `feedback-{n}.md` exists → READY; else if pending followups → concat into `feedback-{n}.md` + READY; else → PENDING_FEEDBACK.

## pin-policy

- Cargo.toml uses caret semver (e.g. `tokio = "1.40"`, `sqlx = "0.8"`). Cargo.lock is committed and locks the exact resolved tree. `cargo audit` reads the lockfile and is the right tool for periodic dep audits.
- DO NOT pin with `=X.Y.Z` strict-equals. We hit this with `toml=0.8.19`: that specific patch had a missing `use serde::ser::SerializeTupleStruct` import, so cargo couldn't compile. With caret semver, resolver picked `0.8.23` automatically and the bug went away. Strict equals blocks neighbor patches.
- When adding a new crate: relax to caret in Cargo.toml; let Cargo.lock pin the exact tree; commit both.

## test-policy

- Global rule (from `~/.claude/CLAUDE.md`): NEVER write tests inline in the current context. ALWAYS invoke `/write-test`. The skill spawns a blind writer (general-purpose subagent — no implementation context) + adversarial reviewer (sees only the tests, suggests removals + additions).
- Gotcha encountered with the db_smoke integration tests: the adversarial reviewer is unaware of NOT NULL schema details and may trim required columns from `INSERT` statements. Before integrating the reviewer's "FINAL" body, manually verify every INSERT supplies all NOT NULL columns in the migration. Pattern: write helper functions `insert_project / insert_task / insert_routine / insert_main_job` that always supply the full required set, then call them throughout tests.
- /write-test integration test workflow: dev-deps must be set up in the target crate's Cargo.toml first (`tokio` full, `sqlx` workspace, `tempfile`). `#[tokio::test]` for async tests.
