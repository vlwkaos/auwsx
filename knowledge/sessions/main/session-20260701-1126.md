## remote-inbound-auwsx-run-daemon

- Added `crates/auwsx-core/src/remote_inbound.rs` as the deterministic daemon boundary for inbound remote `/auwsx-run` events.
- Web/HTTP adapters still own transport concerns: GitHub headers, signature verification, payload normalization, and socket routing.
- `ProcessRemoteAuwsxRunInput` records provider delivery idempotency, resolves project remote config by provider/owner/repo, and uses `remote_plan::plan_inbound_auwsx_run`.
- Accepted events create an approved `Source::Inbox` backlog item, link the remote issue to that backlog item, write a done inbound `remote_sync_runs` audit row, and mark the event processed.
- Duplicate deliveries return `Duplicate` without adding another backlog item.
- Disabled or command-missing events mark the event ignored and leave backlog unchanged.
- Failures after event recording mark the remote event failed with the error text.
- IPC now exposes `Command::ProcessRemoteAuwsxRun` and `Response::RemoteInboundOutcome`; CLI printing has a response arm.
- Added tests for direct inbound processing, duplicate delivery idempotency, disabled toggle behavior, IPC JSON roundtrip, dispatch backlog creation, and event emission.
