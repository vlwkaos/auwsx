## remote-github-webhook-adapter

- Replaced the placeholder `auwsx-web` binary with a thin axum adapter over daemon IPC.
- Endpoint: `POST /webhooks/github`.
- Runtime config: `AUWSX_WEB_ADDR`, default `127.0.0.1:7789`; daemon socket resolves through `auwsx_core::ipc::default_socket_path`.
- The web layer parses GitHub `issue_comment` payloads, computes a SHA-256 payload hash, and normalizes into `Command::ProcessRemoteAuwsxRun`.
- Added `Command::GetProjectRemoteConfigByRepo` so web can resolve per-project config by provider/owner/repo without opening SQLite.
- If `webhook_secret_ref` is set on the project remote config, web reads it as an env var name or `env:NAME` and verifies `X-Hub-Signature-256`.
- Durable mutation remains daemon-owned through `remote_inbound`; web never writes DB state directly.
- Added direct exact workspace deps for already-locked `hex =0.4.3`, `hmac =0.12.1`, and `sha2 =0.10.9`.

## Trials & Solutions

- Needed webhook signature verification but crypto crates were only transitive -> ran supply-chain audit first, then added exact direct deps already present in `Cargo.lock`.
- Avoided having `auwsx-web` read SQLite directly -> added an IPC lookup by provider/owner/repo so the adapter stays a transport boundary.
- Good-to-go gather exits nonzero after printing audit axes -> applied relevant axes manually: docs sync, IPC command roundtrip/dispatch tests, full tests, no-run compile, workspace build, TUI Color grep, and diff whitespace.
