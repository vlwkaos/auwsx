## tui-keybinding-architecture-slice

- Replaced raw capability labels with key-aware `ActionHint` data that formats labels as `(m)ove` or `(Key) label`.
- Remapped TUI grammar:
  - `a` is context add: add project from project/empty context, add backlog from backlog context, add routine from routine context, steer from issue context.
  - `A` is approve/toggle for backlog approval and routine enablement.
  - `Ctrl-,` opens Config.
  - `[` / `]` jump between project headers without daemon round-trips.
- Moved non-context global hints into the right footer next to the version: `(Ctrl-,) config`, `(q)uit`.
- Updated visible backlog approval copy from `a approves` to `A approves`.
- Added tests for new key mapping, add-form routing, project jumping, and stale archived issue steering behavior.

## Trials & Solutions

- Tried making project jump refresh daemon activity immediately -> unit test exposed a daemon dependency in a selection-only action -> removed the refresh and left normal ticks to refresh context.
- Tried preserving old `n`/`p` create actions while adding `a` -> conflicted with requested grammar -> removed those user-facing mappings and routed create through `Action::Add`.
