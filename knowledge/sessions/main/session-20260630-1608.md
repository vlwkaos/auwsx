## reconcile-layer-agentic-queue

- Added `crates/auwsx-core/src/reconcile.rs` as the deterministic classification and validation layer.
- `ProjectReconcileReport` reports per-issue diagnosis, confidence, proposed action, manual command, orphan worktrees, and counts.
- Safe deterministic actions are daemon-owned: mark represented branches DONE, release one clean local merge, prune orphan worktrees, and leave ambiguous states for agentic/manual recovery.
- `project merge` now runs reconcile preflight before release, so represented or conflicting READY_TO_MERGE branches are blocked before entering MERGING.
- Agentic reconcile reuses `main_jobs(kind = "reconcile")`; `reconcile apply` reads a completed job log and applies only validated actions.

## main-jobs-reconcile-queue

- New IPC/CLI surface:
  - `auwsx project diagnose <project_id>` is read-only.
  - `auwsx project reconcile <project_id> --dry-run` is read-only.
  - `auwsx project reconcile <project_id>` applies safe actions and queues one active reconcile main job if blockers remain.
  - `auwsx reconcile apply <job_id>` validates and applies a structured proposal.
- Agent proposals must be final fenced JSON with `schema_version = 1`, `kind = "auwsx_reconcile_proposal"`, and deny unknown fields.
- Apply-time guards re-diagnose current state and reject stale proposals; issue status writes use project/status-checked conditional helpers.
- Reconcile job logs are accepted only from expected `artifacts::main_job_log_path` and are read as a bounded tail.

## recovery-panel-indicators

- TUI project detail now includes a Recovery panel from `ProjectReconcileReport`.
- The panel shows diagnosis counts and top actionable recovery rows.
- It also shows `agent reconcile #<id> running|queued` for active reconcile main jobs.
- It shows `issues <N> running` when recent issue agent runs are open.
- TUI remains read-only for Git/DB mutation; it triggers daemon IPC paths.

## Trials & Solutions

- Tried applying raw/loosely parsed agent output -> unsafe because logs can contain unrelated JSON -> require one final fenced JSON block with schema version and kind.
- Tried trusting diagnosis for apply -> unsafe under concurrent state changes -> re-diagnose at apply time and use conditional project/status writes.
- Tried using report-only TUI Recovery panel -> insufficient for operator status -> add active reconcile main job and issue-agent indicators from existing activity state.
- Tried inspecting `main_jobs.finished_at` and `completed_at` -> schema has `ended_at` -> recorded corrected command in `AGENTS.md`.
- Tried stopping the daemon through `daemon stop` while socket was stale/refused -> used `ping` and live commands to verify the built binary path instead of killing processes blindly.
