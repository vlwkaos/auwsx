## tui-operator-console-ux-and-ask-mode

- Added global Arsenal command presets (`arsenal_presets`, migration `0003`) and project forms can autocomplete/fill per-role agent commands from presets such as `codex` and `claude`.
- Added project ask mode (`ask_answers`, migration `0004`): TUI `?` opens an ask form, CLI supports `auwsx ask <project_id> [--mode recall|seek] <question...>`, and answers are persisted newest-first for later reading/copying.
- Ask execution is daemon-owned via `Scheduler::ask_project`; it snapshots project status, issues, live backlog, and routines, asks the configured main agent to answer once using recall/seek mode, stores the parsed answer plus log path, and emits `Event::AskAnswered`.
- Added issue removal path, context-aware footer hints, cancel-message timeout, backlog promotion consumption, readable last tick labels, and collapsed-project `R/B/I` counts.
- Project overview has a Kanban-style board with broad lanes `TODO`, `IN PROGRESS`, `REVIEW`, `COMPLETE`; detailed issue status remains the authoritative scheduler marker.

## issue-status-board-model

- Broad lane mapping lives in `IssueStatus::stage_label()`:
  - `TODO`: `CONSOLIDATING`, `PLANNING`, `PLANNED`, `PLAN_BLOCKED`
  - `IN PROGRESS`: `IMPLEMENTING`, `NEEDS_FIX`, `COMPLETING`, `CONFLICTED`, `CONFLICT_BLOCKED`
  - `REVIEW`: `REVIEW`, `REVIEW_BLOCKED`, `AUDIT`, `ENDED`
  - `COMPLETE`: `DONE`, `ABSORBED`, `FAILED`
- TUI project child loading sorts issues by `id` ascending before display, so each lane renders oldest-created first.
- Kanban lane order is fixed: `TODO`, `IN PROGRESS`, `REVIEW`, `COMPLETE`.
- In `TODO`, backlog items render before issues; TUI does not currently re-sort backlog beyond daemon-return order.

## agent-log-prettifier

- The full Issue view and the main overview issue detail now share the same Agent Log renderer (`ui::issue::log_block`).
- Log fetch increased from `8 KiB` to `128 KiB`; issue-log scroll state lives in `App::issue_log_scroll`.
- Issue view key behavior: `k` scrolls older, `j` newer, `PgUp/PgDn` page, `Home/End` oldest/newest. Footer hints switch to log-scroll controls while in Issue view.
- Codex JSONL is rendered as bounded transcript blocks:
  - thread/turn/item events become short labels;
  - command events strip shell wrappers such as `/bin/zsh -lc '...'`;
  - `agent_message` text decodes literal `\n` into real lines, indents message blocks, hard-wraps long lines, and caps long pasted code/messages with `... N more lines`.
- The overview issue pane previously rendered `Line::raw(app.log_tail.clone())`, so it bypassed formatting; replacing it with shared `log_block` fixed the main-view right-bottom log.

## issue-pane-layout

- Full Issue view no longer spends a large proportional left pane on fixed metadata. It now uses a fixed 9-line metadata header, with remaining space split between plan/review/steering and the log.
- Main overview issue detail now uses fixed-height issue metadata and phase-detail blocks, leaving flexible vertical space for the Agent Log.
- Labels were clarified:
  - `Subtasks` -> `Plan checklist`
  - `Findings` -> `Review findings`
  - latest log block title uses `Agent log: <filename>`
