## What changed

The whole pipeline was redesigned. OLD model (REPLACED): tasks moving
`BACKLOG→QUEUED→PREPARING→ITERATING→QA→PENDING_FEEDBACK→READY→COMPLETING→KNOWLEDGE_PROPAGATING→DONE`,
agent typed into a detached tmux pane, signal-done/pane-poll completion. NEW
model below. Schema + state machine already reimplemented and green; everything
else is stubs awaiting this model.

## issue-pipeline-model

Decision ledger (authoritative). auwsx is a daemon whose scheduler drives coding
agents against a per-project issue pipeline.

1. **No tmux for agents.** auwsx spawns the agent CLI as a DIRECT child
   subprocess (`tokio::process`); auwsx owns the process. tmux/wsx shell is
   optional, human-only (spectating).
2. **Issue STATUS is the synchronization marker.** Scheduler is a ticker, not a
   process tracker. Tick reads each issue's status → `ACTIONABLE`=spawn the
   phase's agent, `HUMAN_GATED`=wait, `TERMINAL`=archive. Agent exits whenever
   it wants; whatever status it set (via the control CLI) before exiting decides
   continuation. Crash-resume is free: a died agent leaves status untouched, so
   the next tick respawns it.
3. **Agent→auwsx = control CLI over IPC** (`auwsx issue ...`), validated, returns
   IDs, rich content passed as file refs. auwsx NEVER parses agent prose.
6. **Triage auto-groups + promotes** APPROVED backlog into issues — no grouping
   gate (the human gate is at backlog admission, see routines/backlog below).
17. **Role→phase map** (per-project configurable agent CLIs main/plan/work/review):
    triage + CONSOLIDATING = `main` (no worktree); PLANNING = `plan`;
    IMPLEMENTING / NEEDS_FIX / AUDIT / memo + REVIEW(fresh session) = `work`
    (+ optional `review` override); COMPLETING / dream / deepsleep = `main`.
    Worktree created at CONSOLIDATING→PLANNING (standalone only); delegated
    tasks reuse the target's worktree; torn down at DONE.
18. **Concurrency:** serial-per-project v1 (`max_concurrency=1`, one active
    issue/worktree), N projects in parallel; intra-project parallelism later.
23. **Two-path CONSOLIDATING (pre-planning, no worktree yet):** main agent checks
    for a similar in-flight issue in a WORKING phase. If found → fold this task
    in as steering (no new worktree) and self-close to ABSORBED. Else →
    standalone issue → PLANNING (worktree created here).

## issue-status-state-machine

16 states + 3 scheduler classes. `src/state.rs::IssueStatus`; ids == the
`issues.status` CHECK domain in `0001_init.sql` (verified exact, both directions).

```
CONSOLIDATING ─┬─> PLANNING ─> PLANNED ─> IMPLEMENTING ─> REVIEW ⇄ NEEDS_FIX
               │                                            │
               └─> ABSORBED                                 └─> AUDIT ─> ENDED
                                                                          │
   PLAN_BLOCKED / REVIEW_BLOCKED / CONFLICT_BLOCKED (human)          COMPLETING ─> DONE
                                                                          │
                                                                     CONFLICTED ⇄ CONFLICT_BLOCKED
   FAILED reachable from every non-terminal phase.
```

- **SchedulerClass**: Actionable={Consolidating,Planning,Implementing,Review,NeedsFix,Audit,Conflicted,Completing}; HumanGated={Planned,PlanBlocked,ReviewBlocked,ConflictBlocked,Ended}; Terminal={Done,Absorbed,Failed}.
- (5) **Soft-gate-with-timeout** (`issues.wait_until`): PLANNED waits for human N
  min then auto-advances. `is_soft_gated()`=Planned only (ENDED soft only when
  `completion_policy='soft'`, ORed in by the scheduler).
- (7) **QA loop:** durable `.auwsx/` artifacts bridge context. Fresh REVIEW agent
  (3rd eye + devil's-advocate lens) emits findings via `auwsx finding add`;
  implementer is RE-SPAWNED to adjudicate each on record (accept→fix /
  reject→rationale). Loop REVIEW⇄NEEDS_FIX until clean or `review_max_rounds`.
- (8) Review = `work` cmd + fresh session; optional 4th `review` cmd override
  (`review_agent_cmd` NULL→fall back to work).
- (9) Review deadlock after N rounds → REVIEW_BLOCKED (human).
- (15) **CONFLICTED:** work agent attempts rebase/merge resolution; after
  `conflict_max_attempts` → CONFLICT_BLOCKED (human).
- (19) **Completion policy** (per project): `manual` (default, hard gate — human
  checks COMPLETE, no auto-merge) | `soft` (timeout) | `auto` (merge on ENDED).
- (14) **Merge** (local): rebase-to-current (NEVER merge main into branch; no
  mid-branch merges) + single `--no-ff` merge commit; post-merge `/dream` auto on
  default branch. PR mode = `/gh-pr`.
- (20) **Steering:** append-only guidance into a WORKING-phase issue
  (`accepts_steering()` = {Implementing,Review,NeedsFix,Audit}); NEVER edits
  plan.md; sets `has_pending_steering=1` to re-trigger the scheduler. Sources:
  human, consolidation (delegation). `is_working_phase()==accepts_steering()`.
- 37 legal transitions; ABSORBED only from CONSOLIDATING; terminal states have
  zero outgoing.

## agent-auwsx-ipc-contract

(21) **One IPC command surface, two clients:** the agent control CLI and the
human TUI hit the SAME daemon ops. Agent ops ⊆ human ops; IPC enforces per-caller
(agent token vs TUI). Human override is first-class at every gate (force-status,
reject-plan, dismiss-finding, abort, stop-run).

CRUD / command matrix (each row = IPC ops). Actor H=human, A=agent, S=system:

| Entity | ops |
|--------|-----|
| projects | H add / config / rm |
| backlog_items | H+A add; H approve / dismiss / edit / rm; only `approved` → triage |
| issues | S create (from CONSOLIDATING); H edit / status-set(--force) / complete / abort / rm |
| plan (artifact) | A plan-agent only; H approve/reject at PLANNED gate; immutable post-set |
| subtasks | A add; A/H check; H edit / rm |
| findings | A add + adjudicate; H override / dismiss |
| steering | H add; A consolidation-add; H rm pending; guarded by accepts_steering |
| routines | H add/edit/enable/disable/rm/run-now; + builtins |
| main_jobs / routine_runs | S; H stop running; report surfaced after done |
| agent_runs | S; append-only read-only log |
| skills | H path / edit / reseed |

(24) **TUI views** = {Overview, Issue, Backlog, Routines, Logs, Config}; keybinds
bound to this matrix.

## routines-lane

(13) Routines are a SECOND execution lane, scheduled separately from issues.

| type | writes | env |
|------|--------|-----|
| report | nothing | disposable worktree |
| idea | backlog only, via `auwsx draft add` (→ pending) | disposable worktree |
| knowledge (/dream, /deepsleep) | only inside configurable `writable_paths` | main worktree |

- Serialized via the per-project **main queue** (`main_jobs`) so routines never
  race the pipeline (one main-branch writer at a time). `/dream` is BOTH a
  post-merge pipeline step AND a scheduled routine; `/deepsleep` is routine-only.
- **auwsx owns the commit + path-scope check**: routine agent edits in worktree
  and signals done; auwsx verifies the diff ⊆ `writable_paths` BEFORE committing;
  out-of-scope → `main_jobs.status=REJECTED` + flagged. Agent never pushes.
- (16) **Backlog admission gate:** `backlog_items.source` (human|agent|routine|
  inbox) + `approval` (pending|approved|dismissed). human/inbox→approved auto;
  agent/routine→pending. Only `approved` flows to triage.

## skills-injection

(11) auwsx-owned editable skill path (default `~/.local/share/auwsx/skills`,
override via `projects.skill_path`), seeded from the bundle on init, INDEPENDENT
of `~/.claude/skills` (which stays intact for normal agentic work). Mechanism =
per-phase INLINE of the relevant skill text → agent-agnostic (claude/codex/
opencode identical). Essential core: recall, backpressure, simplify, good-to-go,
write-test, commit, memo. Extended: research-mode, sec, gh-pr, write-test-audit,
dream, deepsleep.
(12) KB skills (recall/memo/dream/deepsleep) gated on `ir` presence; graceful
degrade + README/install guidance; not vendoring a separate KB.

## db-schema

`0001_init.sql` REWRITTEN (10 tables, all with CHECK domains):
- **projects**: per-role agent cmds `main/plan/work/review_agent_cmd`,
  `completion_policy`, `completion_soft_timeout_min`, `plan_gate_timeout_min`,
  `iteration_timeout_min`, `main_job_timeout_min`, `review_max_rounds`,
  `conflict_max_attempts`, `max_concurrency`, `merge_mode` (local|pr),
  `skill_path`, deepsleep fields.
- **issues**: status, branch/worktree_path/agent_session (set at PLANNING),
  `review_round`, `conflict_attempts`, `wait_until`, `absorbed_into_id`,
  `has_pending_steering`.
- **subtasks, findings** (severity blocker|major|minor|nit; lens; status
  open|accepted|rejected|dismissed; adjudication), **steering**
  (source human|consolidation; append-only), **backlog_items** (source+approval),
  **routines** (type report|idea|knowledge; writable_paths JSON),
  **main_jobs** (status +REJECTED; report_path; scope_violation),
  **agent_runs** (append-only action log: role/phase/status_before/after/
  exit_kind/log_path/spawned_at/exited_at), **scheduler_runs**.

## Trials & Solutions

- Tried `/tmp` for scratch + sqlite scratch DB → "operation not permitted" → use
  `$TMPDIR` (sandbox blocks `/tmp` writes; `~/ws/auwsx` cargo/git/sqlite need
  `dangerouslyDisableSandbox:true`).
- In-migration `PRAGMA foreign_keys=ON` → no-op (sqlx runs migrations in a
  transaction) → FK enforcement set per-connection in `db/mod.rs` foreign_keys(true);
  removed the misleading PRAGMA.
- Adversarial test reviewer is schema-blind → it guessed `findings.severity='high'`
  for a positive control → invalid (domain is blocker|major|minor|nit) → corrected
  to 'major'. Lesson: always check reviewer-invented domain values against the SQL.
- `git mv` of a module makes the new path "unread" → Write tool refused until a
  fresh Read of the new path.
- db/mod.rs has no typed CRUD; insert helpers live in the test files — so the
  schema rewrite only broke tests/db_smoke.rs (regenerated), not the lib.
