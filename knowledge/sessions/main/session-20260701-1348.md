## remote-pipeline-e2e

- Added ignored e2e test `deterministic_agent_drives_remote_issue_and_pr_pipeline` in `crates/auwsx-tui/tests/local_merge_e2e.rs`.
- Test starts the real auwsx daemon and talks through the real `auwsx` CLI.
- Test initializes a real Git repo/worktree pipeline, uses the deterministic agent to drive a backlog into `READY_TO_MERGE`, then queues PR merge through `auwsx project merge`.
- Test installs a fake executable named `gh` in the repo-local temp directory and prepends that path to the daemon environment.
- Fake `gh` handles:
  - `gh issue create`
  - `gh pr create`
  - `gh pr view --json ...`
  - `gh issue comment` / `gh pr comment`
- Assertions cover remote issue link, PR link, merged PR observation, green check status, outbound issue sync run, outbound PR sync run, inbound PR observation run, and fake `gh` invocation log.
- The e2e is ignored by default because it spawns daemon/git worktrees, but was run explicitly this session.

## Trials & Solutions

- The CLI does not expose project `merge_mode` on `project add`; the e2e sets `merge_mode=pr` via typed DB update after project creation so it can focus on remote pipeline behavior.
- Real GitHub is not required for CI-safe e2e; a fake `gh` executable still validates the subprocess boundary and provider command shapes.
