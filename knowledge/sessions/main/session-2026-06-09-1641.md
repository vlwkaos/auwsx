## autonomy-loop-architecture

Built the full autonomy loop on top of the daemon spine (commit `ced3c47`). The
orchestrator now drives issues autonomously. **Verified LIVE**: the real daemon
drove an issue CONSOLIDATING→PLANNING→PLANNED via real agent subprocesses that
called back over the socket (`auwsx issue status …`), creating a real git
worktree at PLANNING, then parked correctly at the PLANNED soft gate. 416 tests
green (33 new in `tests/autonomy.rs`).

### Architecture: ports & adapters (hexagonal)
Domain logic is pure + testable; infrastructure sits behind traits so the whole
drive loop runs deterministically with fakes (no real process/git/clock).

| Port (trait) | Prod adapter | Why isolated |
|--------------|--------------|--------------|
| `clock::Clock` | `SystemClock` | scheduler decisions deterministic under test (fixed clock) |
| `agent::AgentExecutor` | `SubprocessExecutor` (→`agent::run`) | THE drive-loop seam: a fake reads `AUWSX_ISSUE_ID` from `spec.env` and applies the transition a real agent would make via the CLI — no real process needed |
| `worktree::Worktrees` | `WsxWorktrees` (wsx_core::ops via `spawn_blocking`) | test with a temp-dir fake; wsx-core ops are SYNC so wrap in spawn_blocking |

### Pure domain (test without IO)
- `pipeline::plan_phase(status) -> Option<(Role, needs_worktree)>`. Some-set == `is_actionable`. Consolidating→(Main,false); Planning→(Plan,true); Implementing/NeedsFix/Audit/Conflicted/Completing→(Work,true); Review→(Review,true).
- `scheduler::decide(issues, project, running, now) -> Vec<Decision>` where `Decision = Spawn|SoftGate|Teardown`. Caps spawns at `max_concurrency - running.len()`; skips running issues; emits `SoftGate` only when due (`soft_gate_due`: soft-releasable AND (`wait_until` None OR now≥wait_until)); `Teardown` for Done-with-worktree only.
- `prompt::build(&PromptContext) -> Option<String>` — per-phase prompt; None iff non-actionable.

### Effectful (uses ports + db)
- `pipeline::execute(&Deps, issue_id)`: load issue→plan_phase→ensure worktree (only if needs_worktree && worktree_path None; persist branch/path)→cwd = worktree else repo_path→load steering/subtasks/findings→build prompt→`agent_runs::start`→`executor.execute(AgentSpec)`→reload status for `status_after`→`agent_runs::finish`. Run logs/prompts under `AUWSX_DATA_DIR`/`<data>/runs/issue-N/` (NOT in repo — agent writes its own `.auwsx/` artifacts there).
- `Scheduler` (Clone; holds Arc<dyn ports> + Db + bus + socket + `running: Arc<Mutex<HashSet>>` + `inflight: Vec<JoinHandle>`): `tick_project` decides + dispatches; `spawn_phase` reserves the slot and spawns a task that self-removes from `running` on completion; `service_soft_gate` arms `wait_until` (=now+timeout_min*60_000) or releases (transition) when `deadline<=0` (auto) or due; `teardown` removes worktree + clears fields; `join_inflight` (tests/drain); `prune_inflight` (drop finished handles so the Vec doesn't grow). `run(shutdown)` ticks all projects every `tick_interval`.

### Agent callback contract (decided this session)
Agent reports back by running the SAME `auwsx` CLI as a thin IPC client. Pipeline
injects `AUWSX_SOCK` + `AUWSX_ISSUE_ID` + `AUWSX_AGENT_ROLE` into the child env;
prompts tell it to run `auwsx issue status "$AUWSX_ISSUE_ID" <NEXT>`. No per-run
token/scoping yet — local 0700 socket is the v1 boundary (deferred).

### Daemon wiring
`run_daemon`: IPC server + `Scheduler::run` concurrently over one Db + bus.
`ipc::serve` keeps its `Arc<Notify>` shutdown (so the 65 ipc tests stand); the
scheduler gets its OWN stop `Notify`, fired after `serve` returns (SIGINT or
`daemon stop`), then its task is awaited. Tick cadence `AUWSX_TICK_SECS` (default
10) — short so the loop reacts when an agent advances an issue.

## drive-loop-test-pattern
The deterministic end-to-end test: `FixedClock` + `FakeWorktrees` (temp dir, no
git) + `ScriptedAgent` (impl `AgentExecutor`: reads `AUWSX_ISSUE_ID` from env,
looks up current status, applies the next transition via `issues::transition`,
returns `Exited/0`). Project set to `completion_policy='auto'` +
`plan_gate_timeout_min=0` (raw sqlx UPDATE) so soft gates release with NO time
travel. Drive by hand: loop `tick_project` + `join_inflight` until Done. Asserts
Done reached, worktree torn down, every `agent_runs` row finished with
`status_after` + `exit_kind=Exited`. PLANNED→IMPLEMENTING and ENDED→COMPLETING
are scheduler soft-gate releases, NOT agent transitions.

## Trials & Solutions
- Tried `decide(now)` with `now` unused (timing only in `service_soft_gate`) → clippy unused-var → moved due-ness into `decide` via `soft_gate_due(issue, project, now)` so it only emits SoftGate when arming-needed or expired (less churn, `now` meaningful).
- Daemon shutdown: `ipc::serve` waits on `Notify`; sharing ONE Notify with the scheduler would only wake one (`notify_one`) → gave the scheduler its OWN stop Notify fired after serve returns; kept serve's signature so ipc tests stand. (CancellationToken would wake all but would churn the 65 ipc tests.)
- wsx_core worktree ops are synchronous (shell out to git) → wrapped in `tokio::task::spawn_blocking` inside the async `Worktrees` adapter.
- Demo cleanup `rm -rf` blocked by sandbox on `.git` files → needs `dangerouslyDisableSandbox`.
